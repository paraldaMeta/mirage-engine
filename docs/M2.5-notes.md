# M2.5 notes — a minimal game engine

M2.5 adds `packages/game` (`@mirage/game`) and `examples/garden-quest`, with small changes to `@mirage/play`
(pluggable walker, input and per-step hook) and to walled-garden's pavilion module (optional door leaves, a
`doors` anchor, a renamable lamp anchor). All new code is Mirage original code; nothing comes from the author's
earlier project or from Golden Temple.

## What

- **Entities**: plain objects in a Map (`game.add / remove / spawn(anchors, make)`), systems as functions run each
  tick, events (`on / emit`), flags, an inventory, interactables (`interact: { label, can, use, reach }`; the
  nearest one inside a cone around the view gets the prompt), save / load / export / import, pause.
- **Physics** (Rapier): one static trimesh collider per solid mesh, chosen by the walk grid's rule (30 colliders,
  158 k triangles for the garden, 43 ms); dynamic props (`body`), kinematic hinged doors (`hinge`), rays with the
  surface under them, and a kinematic character controller with the walk grid walker's interface, plugged into
  `createPlay({ walker })`: walk 1.5 m/s, run 4.2, jump 4.2 m/s, autostep 0.4 m, snap to ground, slopes ≤ 46°,
  pushes crates and a ball. Doors are kinematic bodies, so moving doors no longer need a re-bake (M2's open
  problem): the pavilion's two leaves swing open and closed and block / pass the character.
- **Walk grid kept** next to physics: it is pure JS (no WASM, works in node and in `mountWorld` hosts), answers
  ground and clearance queries in O(1) for agents, tools, fly mode and viewpoints, and is what navigation
  (recast, later) would be built from. It describes the static architecture only: the game's entity group has
  `collide = false`, so doors and props are left out of it and live in physics.
- **Input**: an action map (`forward back left right run jump interact inventory menu`) over the keyboard
  (rebindable; bindings saved in each save and in a settings key), the Gamepad API (standard mapping, dead zone,
  right-stick look, d-pad / A / B in menus) and touch (virtual stick, drag-look, Jump / Use / Bag / ☰ buttons,
  shown on coarse pointers or the first touch). Mouse look stays in play (pointer lock, or drag).
- **Audio**: Web Audio, buses master → music / sfx / ambience, HRTF panners with inverse-distance falloff, the
  listener following the camera. Every sound is generated in code at unlock (310 ms): footsteps for stone, gravel,
  grass and wood (4 variants each, pitch and level jitter), pickup chime, lock rattle, door creak and thud,
  ignition, the done chime, loops for wind with birds, water (the basin and both pools, placed in 3D) and a pad.
  No audio files, so nothing new in CREDITS beyond Rapier.
- **UI**: an HTML / CSS overlay, no framework: objective, carried items, crosshair, prompt with the current
  device's glyph (E / X / Use), toasts, a start screen (unlocks audio), the pause menu (resume, 3 save slots,
  load, export to / import from a file, controls with rebinding, volume sliders, restart), an inventory panel
  and a message dialog. Native modal `<dialog>`s (focus stays inside, labelled), real buttons and range inputs,
  aria-live prompt and toasts, visible focus rings; Escape / P / Start toggle the menu, losing pointer lock pauses.
- **garden-quest**: walled-garden's modules on its plan (same seed, so the same trees) plus a `stands` module;
  the key lies on a bench in the lower garden, the pavilion door is locked until you carry it, a lit taper waits
  on the bench inside, four lanterns (two hanging inside, two on the stands outside) light up one by one, then a
  "done" message. Three crates and a ball to push about. A low sun (2.2°) so the garden's own lanterns begin to
  glow. Single file 4.31 MB.

## Library decisions

| need | choice | licence | size | why |
|---|---|---|---|---|
| physics | `@dimforge/rapier3d-compat` **0.19.3** (Nov 2025) | Apache-2.0 | WASM 1.57 MB, inlined as base64: 2.24 MB JS, 0.84 MB gzip | mature, character controller built in; the compat build embeds the WASM, so the single file opens from file:// with no fetch. 0.21.0 (Sep 2026) is 3.08 MB WASM / 4.34 MB JS (soft bodies, voxels we do not use): skipped. Loaded by dynamic `import()` → its own chunk; pages without `createPhysics` never load it |
| entities | plain objects + functions | — | 0 | bitECS (MPL-2.0, 1.75 MB unpacked) and Koota (ISC, 0.5 MB, React-leaning) pay off at ~10⁴ entities in typed arrays; a game of a few dozen interactables is clearer, and saves as JSON, without them (ponytail comment in `game.js`) |
| audio | Web Audio `PannerNode` directly | — | 0 | three's `PositionalAudio` wraps the same nodes and needs the camera in the scene graph |
| UI | DOM + native `<dialog>` | — | 0 | focus handling and Escape semantics for free |

Measured on the KCC: a capsule's round bottom climbs the garden's 0.178 m risers at about a third of the walking
speed under Rapier's autostep; a flat cylinder at ~92 %, so the character is a cylinder (like the walk grid's
body). The compat build's init prints a wasm-bindgen deprecation warning; `loadRapier` filters exactly that line.

## Numbers (Apple M4 Pro, ANGLE Metal, Chrome headless, 1440 × 900)

- **Playthrough** (`examples/garden-quest/scripts/playthrough.mjs`, real key / pad / touch events), served over
  http and as the single file from file://: **37 / 37 steps pass both times, 0 console errors or warnings**.
  Main (19 steps): start → walk ~45 m to the key → prompt → pick up (chime) → walk ~37 m and two flights up to the
  pavilion → prompt "Unlock the door" → door opens (both leaves at ±1.45 rad, creak) → save to slot 1 from the
  menu → resume → **reload the page** (fresh: no key, door shut) → load slot 1 from the menu → same position
  (0, 3.52, −19.585 → 0, 3.52, −19.585), key carried, door open → enter → take the taper → light lanterns 1–4
  (ignite × 4) → "The lanterns are lit" dialog (done chime). Footsteps: 149 stone, 11 gravel (grass and wood are
  checked in node; the hedged lawns are not walkable). Save file 1.07 kB. Gamepad (11): A starts, left stick walks
  3 m in 2 s, right stick turns > 0.6 rad, A jumps (> 0.6 m), X picks up, Y opens the bag, B closes, Start opens the
  menu, d-pad moves focus to Load, A presses it, B resumes. Touch (7, 390 × 844, mobile + touch emulation): touch
  UI shown, stick walks 2.8 m, drag looks, Jump jumps, Use picks up, ☰ opens the menu, Resume resumes.
- **Frame cost** (`perf.mjs`, synchronous, 1-px readback, mean / p95 of 120, physics + game tick inside):
  garden-quest walk 4.34 / 4.8 ms, game view 4.0 / 4.5, fly 4.04 / 4.4; still path spp 6 16.6 ms, spp 16 41.4 ms;
  98 draw calls, 0.41 M triangles (walled-garden on the same run: walk 3.73 / 4.2, game 3.71, fly 4.38; spp 6
  19.5 ms; 60 calls — the extra calls are the entity meshes, the extra point lights cost the still path nothing
  measurable). Physics + character + game tick alone: 0.55 ms mean, 1.2 ms p95 a frame. Single file: walk
  4.28 / 4.8 ms.
- **Load**: Rapier chunk 2.24 MB fetched and initialised lazily (5 ms fetch locally); colliders 43 ms; setup to
  playable 0.83 s warm, 7.5 s on a first load in a fresh profile (shader compilation, as in M2); page load to
  ready 1.66 s warm.
- **Bundle sizes** (Vite, minified): walled-garden (no game) JS 882.8 kB (239.2 kB gzip). garden-quest: main chunk
  923.8 kB (254.8 kB gzip: +41 kB / +15.6 kB gzip for `@mirage/game` and the quest) + the lazy Rapier chunk
  2236.7 kB (842.3 kB gzip). Single files: walled-garden 2.14 MB, garden-quest 4.31 MB (1.30 MB textures,
  3.02 MB code of which 2.24 MB is Rapier).
- **Regression**: `npm test` (core, world, play, game) ok; walk tests 12 / 12 (courtyard), 16 / 16 (garden);
  still-frame identity: all 7 courtyard and 10 garden snapshots (every viewpoint + game view, spp 6) rendered with
  the M2.5 code are bit-identical to the same views built from M2 (0 differing pixels).

## Open problems / not done

- **Physics**: one variable-length step per frame (clamped to 1/30 s), no fixed step or interpolation, so not
  deterministic; no sensors / contact events (interactables use distance); static colliders are built once at load
  (no streaming, no per-module rebuild); trimesh per mesh, no convex decomposition for dynamic props (boxes and balls
  only). A leaf closing on the player is untested (kinematic vs kinematic: no push-out).
- **Character**: no crouch, ladders, swimming or moving-platform carry; the jump apex is ~0.3 m higher when jumping
  into an obstacle (autostep lifts mid-air); loading a save restores the exact feet position, without a check
  that the spot is still free.
- **Walk grid vs physics**: they can disagree at thin features (the grid samples 0.125 m columns); the grid does not
  see doors or props, so agents querying it treat doorways as open / closed as baked.
- **Input**: one gamepad; no per-action gamepad rebinding (fixed standard layout), no mouse-button bindings, no
  look sensitivity or invert setting; touch has no run toggle.
- **Audio**: no reverb or occlusion (the pavilion interior sounds like the garden); sounds are generated on the main
  thread at unlock (310 ms hitch once); grass and wood footsteps never occur in garden-quest's route.
- **UI**: English only; no screen-reader test was run (structure: dialogs, buttons, live regions); the start
  screen is needed for audio and pointer lock, and pressing A on it also jumps.
- **Game**: no animation of the player (first person only in the game; the G view is disabled by `devKeys: false`),
  no NPCs, dialogue or navigation; quest logic is plain code in `quest.js`, not data.
- **Size**: the single file is 4.31 MB, under the 5 MB budget but half of it is Rapier; a gzip-in-base64 loader
  would cut ~1.4 MB.
