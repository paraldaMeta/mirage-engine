# 独立造景任务 · 雨后测候站

请从空目录做一个可离线打开的 Mirage 网页场景。雨刚停，一条山路通往有屋顶的测候站；玩家从路口走进站内，在仪表前按 E，点亮从门外也能看到的琥珀色信号灯。走回门口时，灯仍亮着。路边有一道看得见、挡得住人的护栏。布局、造型和配色由你决定。场景使用原创程序化几何和材质，交付单个不超过 5,000,000 字节的 HTML。

**起点**。从本工作区的 `agent/mirage-router/SKILL.md` 开始。可以使用随附的七个技能、其模板、世界协议和本地包文档。若必须翻引擎源码才能继续，请在日志中写下所缺的说明和文件位置。只用本工作区；独立用一个新会话完成，不调用其他 Agent，不使用网页、其他项目、成品示例或以前的聊天。可以反复使用本地引擎和 Chrome 自测。

**工程约定**。在 `examples/rain-post/` 内交付入口、布局、至少三个有实质几何或交互职责的模块、`BRIEF.md`、`NOTES.md`、自己的试玩脚本（固定入口为 `scenarios/playtest.json`）和 `TRIAL-LOG.md`。至少有一处实际的跨模块挂点消费。使用 Mirage 的正常加载、走动和交互入口。引擎、技能及测试工具属于固定输入。允许技能随附的空骨架。除引擎已有的工作区依赖外，场景只使用本地源码，无第三方素材或服务。

**给后续验收的接口**。在场景目录交一份 UTF-8 的 `handoff.json`，包含下列字段。坐标必须对应实际建造的位置，标记必须能在源码和画面中找到。

| 字段 | 约定 |
|---|---|
| `route` | 从真实出生点到仪表可操作位置的有序 `[[x,z], …]`，至少 3 点，路线不少于 12 米，起终点至少相距 8 米；相邻点各异，倒数第二点是站门外的观察点，与终点至少相距 1.5 米 |
| `railEye` | 玩家正对护栏时的眼睛位置 `[x,y,z]`，前方约 1 米处是可见栏杆，位于可走区域内部 |
| `railLook` | 栏杆另一侧的注视点 `[x,y,z]`，与眼睛水平距离至少 2 米，向前走 3 米会穿越栏杆所在位置且仍在场景可走边界以内 |
| `switchId` | 仪表上可用 E 操作的实体 ID |
| `signalLook` | 门外回头看琥珀灯时注视的世界坐标 `[x,y,z]` |
| `signalFlag` | 简单标识符形式的游戏状态名，开始为显式布尔值 false，操作后为 true |
| `signalAnchor` | 构建报告中可找到的挂点名；一个模块提供，一个不同的模块声明消费，用于仪表或信号灯 |

场景响应 `?start=1&quality=medium`，就绪时可直接行走并使用 E。操作后无需打开菜单或重新出生即可离开。前三个机位各有不同的名字和构图。中档目标为 1440 × 900、平均每帧不超过 16.7 ms、路线闪烁均值小于 8。按技能自测 HTTP 和离线单文件，检查截图。保留自己的报告和原始失败；只把实现源码和日志作为提交，不在日志里写客户端名称。不要上传或发布。

**过程记录**。在 `TRIAL-LOG.md` 按时间追加「时间、读了哪份技能、执行了什么、看到的错误或歧义、如何恢复、证据路径」。写明首次可走、首次成功交互、首次单文件通过的时间，记录所有人工提示。遇到阻塞可正常报告，到规定时间即交当前版本。不要补造截图、时间或结果。
